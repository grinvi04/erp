# 유료 파일럿 법률 검토 인계서

> 상태: **법률 검토 요청 준비 완료 — 법률 자문 또는 최종 문안이 아님**
>
> 법령 확인 기준일: 2026-07-16
>
> 적용 예정 범위: 대한민국 소규모 무역·유통업 고객 1개사, Finance·Inventory·CRM

이 문서는 대한민국 개인정보 보호법에 자격이 있는 검토자가 계약·개인정보 문안을 확정할 때 필요한 제품 사실, 질문, 산출물과 승인 증거를 한곳에 모은 인계서다. 법적 역할, 적법 근거, 보존 의무, 신고 시한 또는 책임 한도를 제품 코드나 이 문서가 결정하지 않는다.

## 1. 검토자가 먼저 확인할 입력

| 입력 | 현재 상태 | 정본 또는 확인 방법 |
|---|---|---|
| 사업 범위·금지 데이터 | 승인됨 | [개인정보·법률 준비 기준](privacy-legal-readiness.md) §1~2 |
| 서비스 수준·지원·반출·파기 초안 | 제품 소유자 승인됨 | [서비스 운영 정책](service-policy.md) |
| 보안·복원 절차 | 로컬 절차 검증, 운영 증거 없음 | [운영 런북](operations-runbook.md), GitHub #189 |
| 실제 계약 당사자·사업자등록 정보 | 미정 | 서명 전 제한된 계약 저장소에서 확인 |
| 고객의 실제 개인정보 처리 목적·항목 | 승인 범위 내 확인 필요 | 고객 확인서 또는 주문서 부속서 |
| Vercel·Railway 계약 플랜·DPA·실제 리전 | 결제 보류로 미정 | 결제 후 계정 원본과 공급자 문서에서 확인 |
| 독립 백업 저장소·지원 채널 | 미정 | 공급자 선정 후 DPA·국가·보존 설정 확인 |

HR, 급여·인사 데이터, 민감정보, 고유식별정보와 미성년자 데이터는 첫 파일럿에서 제외한다. 이 범위를 넓히는 것은 이 인계서의 검토 결과만으로 승인되지 않으며 별도 영향 검토와 제품 게이트가 필요하다.

## 2. 법률 검토 질문

### 처리위탁과 재위탁

- 고객사, ERP 사업자, 인프라·백업·지원 사업자의 역할을 실제 계약과 데이터 흐름에 맞게 확정한다.
- 개인정보 보호법 제26조 제1항의 문서 요건인 목적 외 처리 금지와 기술적·관리적 보호조치를 DPA에 반영하고, 감독·점검, 접근 제한, 사고 통지, 반환·삭제, 책임 범위를 함께 검토한다.
- 제26조 제2항에 따른 위탁 업무와 수탁자 공개 범위에 재수탁자가 포함되는지, 고객과 ERP 사업자가 각각 무엇을 공개해야 하는지 확정한다.
- 제26조 제6항의 재위탁 전 위탁자 동의를 공급자 목록, 사전 변경 통지, 이의제기·해지 절차와 어떻게 연결할지 확정한다. 단순 통지만으로 동의 요건을 충족한다고 가정하지 않는다.
- ERP 사업자가 Vercel·Railway·백업·지원 사업자를 감독하고 변경 이력을 남길 현실적인 방법을 계약에 반영한다.

### 국외 처리

- 개인정보 보호법 제28조의8이 허용하는 국외 이전 근거 전체 중 적용 가능한 근거를 실제 B2B 관계와 각 데이터 흐름별로 확정하고, 근거별 고지·계약·동의 요건을 검토한다. 이 문서는 특정 근거를 미리 선택하거나 선택지를 제한하지 않는다.
- 이전받는 자, 국가, 이전 항목·시기·방법, 목적·보유기간, 거부 방법과 거부 효과 등 필요한 고지·동의 항목을 확정한다.
- Next.js BFF의 인증 세션과 업무 API 응답, Railway의 애플리케이션·DB·Keycloak·로그, 독립 백업과 지원 첨부자료를 각각 검토한다.
- 검토 시점의 시행 법령과 2026-08-20 시행 예정 개정의 적용 여부를 다시 확인한다. 서명 직전에도 최신 법령과 공급자 하위처리자 목록을 재확인한다.

### 보유·파기·정보주체 요청

- 운영 데이터 30일, 백업 최대 90일이라는 제품 정책이 세법·상법 등 법정 보존, 분쟁 보존과 고객 계약에 부합하는지 데이터 범주별로 확정한다. Railway의 월간 백업 표기인 `3개월`은 달력 계산에 따라 90일을 넘을 수 있으므로, 실제 삭제 계산·설정을 확인해 계약의 최대 보존기간과 일치시키기 전에는 승인하지 않는다.
- 보존 예외의 법적 근거, 대상 범위, 접근권한, 종료일과 재검토자를 기록하는 형식을 확정한다.
- 열람·정정·삭제·처리정지 요청에서 고객사와 ERP 사업자의 접수·본인확인·처리·통지 책임과 기한을 확정한다.
- 백업 복원으로 파기 대상 데이터가 되살아난 경우의 재삭제 절차와 증거가 법률 문안과 운영 런북에서 일치하는지 검토한다.

### 사고·상용 계약

- 서비스 운영 정책의 P1 고객 통지 목표와 법정 신고·정보주체 통지를 구분하고 주체, 판단 기준, 기한, 협력 의무와 증거 보존을 확정한다.
- 주문서·이용약관·DPA·보안 부속서 사이의 우선순위, 책임 제한, 면책, 준거법, 종료와 데이터 반출 조건을 확정한다.
- 전자세금계산서·회계 데이터의 보존 및 고객 책임을 확인하고, 개인정보 파기 약속과 충돌하지 않도록 예외를 명시한다.

## 3. 요청 산출물과 완료 증거

| 산출물 | 최소 확인 내용 | 완료 증거 |
|---|---|---|
| B2B 계약·주문서 | 제공 모듈, 지원, 가격, 책임, 종료·반출 | 문서 ID·버전·검토자·승인자·효력일 |
| 개인정보 처리위탁/DPA | 역할, 지시, 제26조 요건, 재위탁 동의, 감독, 사고, 반환·삭제 | 동일 |
| 개인정보 처리방침 | 직접 처리 데이터, 처리 근거, 보유기간, 권리 행사, 위탁 공개 | 동일 |
| 국외 이전 고지·동의 문안 | 흐름별 적법 근거와 필수 고지 항목 | 동일 |
| 하위처리자 목록 | 업체·업무·국가·보유, 변경 통지·동의·이의 절차 | 공급자 원본 보관 위치와 확인일 |
| 보안 사고 부속서 | 운영 통지와 법정 통지, 협력·증거·책임 | 동일 |
| 반출·보존·파기 부속서 | 형식·기한, 법정 보존 예외, 플랫폼 보존 계산, 백업 재삭제 | 동일 |
| 고객 범위 확인서 | HR·금지 데이터 제외, 자유입력 주의, 고객 담당자 | 서명 증거의 제한 저장소 위치 |

각 산출물은 `초안 → 법률 검토 → 제품 소유자 승인 → 고객 합의` 상태를 구분한다. 검토 의견만 도착했거나 공급자 정보가 `미정`이면 완료로 표시하지 않는다.

## 4. 저장·승인 기록 규칙

- 공개 저장소와 GitHub 이슈에는 문서 ID, 버전, 상태, 검토자·승인자, 효력일과 제한 저장소 위치만 기록한다.
- 서명 원문, 사업자등록증, 신분증, 계약 금액, 고객 개인정보와 실제 접근 토큰은 올리지 않는다.
- 법률 검토 의견이 제품 동작·보존기간·삭제 범위를 바꾸면 별도 스펙과 PR로 구현하고 반증 테스트를 거친다.
- 공급자 플랜·DPA·리전이 미정인 동안 국외 처리와 하위처리자 게이트는 열린 상태로 둔다.

## 5. 법령·공식 참고자료

- [개인정보 보호법 제26조](https://law.go.kr/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900079876): 처리위탁 문서, 공개, 감독, 목적 외 이용 금지, 재위탁 동의
- [개인정보 보호법 제28조의8](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=270351): 개인정보 국외 이전
- [개인정보 보호법 시행령 현행 정보](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0028&lsiSeq=286175&urlMode=lsScJoRltInfoR): 검토일 현재 시행령 원문과 시행일 확인
- [2026-08-20 시행 예정 시행령 개정](https://www.law.go.kr/LSW/lsInfoP.do?ancYnChk=0&chrClsCd=010202&efYd=20260820&lsId=&lsiSeq=283503&urlMode=lsEfInfoR&viewCls=lsRvsDocInfoR): 서비스 서명·출시일 기준 적용 여부 재확인
- [개인정보 처리 업무 위탁 표준계약서](https://law.go.kr/flDownload.do?flSeq=129867167): 계약 초안 비교용 공식 서식

공식 서식과 링크는 법률 검토를 대체하지 않는다. 법률 검토 착수일과 계약 서명 직전에 원문 시행일·개정 이력과 개인정보보호위원회 최신 지침을 다시 확인한다.
