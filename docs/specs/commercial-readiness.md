# commercial-readiness 스펙

## 1. 목표 & Why

기존 제품 방향을 유지한다: **국내 소규모 무역·유통업(약 20명)의 다통화 수입·국내 재판매**를 위한 멀티테넌트 ERP다. 이 기능군을 유료 파일럿 고객이 실제 업무에 사용할 수 있도록, 데이터 누락 위험을 제거하고 출시·운영·복구 가능성을 검증 가능한 릴리즈 게이트로 만든다.

**성공 기준(측정 가능):** 파일럿 테넌트가 격리된 운영 환경에서 기준정보 설정 → 회계기간 생성 → 매입/매출·재고 이동 → 결재 → 재무제표·부가세 신고서·CSV 내보내기를 완료하고, 복구 연습 및 출시 게이트가 모두 통과한다.

### 감사 근거 (2026-07-12, 현재 워크트리 + GitHub)

- 과거 Tier 0/1 리메디에이션은 현재 코드와 병합 이력으로 완료가 확인된다: 회계기간 UI, FX, 소프트삭제·낙관적 잠금·400 응답, 결재·재고 이동·리드 전환.
- GitHub의 열린 이슈는 두 건이다. **#171**은 필터와 5,000행 상한을 함께 쓸 때 CSV 결과가 조건 일치 행을 누락하는 실제 정확성 결함이다. **#172**는 코드와 단위 테스트에서 이미 구현된 CRM 집계 스코프/참조 엔티티 잠금에 대한 오래된 추적 이슈로, 재검증 후 종결 대상이다.
- 운영 배포는 아직 존재하지 않으며(`README.md`, `docs/deployment.md`), 백업·복구·장애 대응·개인정보/계약 문서는 저장소에 없다. 따라서 현재 상태를 "유료 상용 서비스"라고 주장할 근거는 없다.
- 로컬 `develop`은 `origin/develop`보다 2커밋 뒤다. 구현 시작 전 최신 `develop`을 별도 작업 브랜치의 기준으로 재확인한다.

### 구현·검증 현황 (2026-07-13, `feature/commercial-readiness`, Draft PR #184)

- 태스크 1~5의 로컬 구현과 검증을 완료했다. #171의 필터 내보내기 정확성, #172의 CRM 데이터스코프·참조 잠금, 핵심 업무흐름, 복구 스크립트·런북, 보안 헤더·세션 경계를 코드와 테스트로 고정했다.
- 릴리스 재감사에서 발견된 추가 결함도 해소했다. 브라우저 세션의 access token 제거, 요청별 nonce CSP, 운영 SecurityConfig 결선, 위험한 암묵 관리자 bootstrap 제거, Tenant 감사·낙관적 잠금·소프트삭제 DB 표준을 적용했다.
- 운영 인증 체인은 실제 PostgreSQL에서 `JWT → DB 역할 권한 → ACTIVE tenant → API 200`과 `SUSPENDED tenant → 403/C004`를 검증한다.
- 로컬 게이트는 backend `check`, frontend test/type-check/lint/design/build, 기본 Playwright 35건, 실제 Keycloak·Backend Playwright 7건, migration safety, 의존성 감사를 통과했다. 로컬 PostgreSQL 16 격리 복원 연습도 통과했다.
- 브랜치를 push하고 `develop` 대상 Draft PR #184를 생성했으며, 후보 SHA `b465960`에서 GitHub Actions 10개와 독립 AI 리뷰가 통과했다. 미해결 리뷰 스레드는 0개이고 PR은 mergeable 상태다. #171·#172는 기본 브랜치 대상 PR이 아니어서 GitHub 자동 종결 대상이 아니며, develop 반영과 증거 확인 후 별도로 종결한다.
- 아직 완료되지 않은 것은 태스크 6과 외부 변경이다. Railway/Vercel/Keycloak 운영 환경·UAT·운영 백업·법무/SLA 결정은 계정과 제품 소유자 승인이 필요하다. 따라서 현재 커밋은 **검증된 파일럿 배포 후보**이지 운영 출시 승인 상태가 아니다.

## 2. Scope

- **In:** #171 CSV 정확성 수정, #172 재검증, 파일럿 업무흐름 E2E, 배포 전 릴리즈 게이트(백업·복구 연습 포함), 최소 운영 문서와 보안 헤더 검증, 유료 파일럿 온보딩 체크리스트.
- **Out (Non-goals):** 급여/연말정산, 제조·BOM, 국세청 직접전송, 다국가 법규 지원, 결제·구독 청구, ISMS 인증 획득. 이들은 판매 준비와 별도의 제품/법무 결정이 필요하다.

## 3. 기능 요구사항 + 수용기준 (= 테스트 계약)

- **AC-1 (정확성):** WHEN 사용자가 화면 필터 조건으로 CSV를 내보내면, the system SHALL 필터와 일치하는 모든 행만 서버에서 조회하고, 5,000행 상한 초과 시 누락 없이 명시적으로 실패/안내한다.
- **AC-2 (격리):** WHEN 다른 테넌트 또는 데이터스코프 제한 사용자가 목록·집계·내보내기를 요청하면, the system SHALL 권한 밖 행을 응답·CSV·집계에 포함하지 않는다.
- **AC-3 (핵심 흐름):** WHEN 파일럿 테넌트가 회계기간·거래처·품목·계정을 설정한 뒤 매입/매출, 창고간 이동, 결재를 수행하면, the system SHALL 전기·재고·부가세·재무제표 결과를 해당 테넌트에 정확히 반영한다.
- **AC-4 (복구):** WHEN 운영 데이터베이스 백업을 새 PostgreSQL 인스턴스에 복원하면, the system SHALL Flyway 이력·파일럿 테넌트 데이터·로그인 후 핵심 조회를 복구 체크리스트로 검증할 수 있다.
- **AC-5 (출시 게이트):** WHEN 릴리즈 후보가 생성되면, the system SHALL backend check, frontend type-check/lint/design/test/build, 핵심 Playwright E2E, 의존성·시크릿 점검 및 수동 복구 연습 결과를 기록해 모두 통과한 경우에만 파일럿 배포 후보로 판단한다.
- **AC-6 (보안 기본선):** WHEN 브라우저가 공개 앱을 요청하면, the system SHALL 인증·세션 흐름을 깨지 않는 검증된 보안 응답 헤더를 반환하고, 운영 환경의 시크릿·개인정보를 소스/로그/클라이언트 번들에 노출하지 않는다.

## 4. 제약 / 비기능

- 테넌트 격리·RBAC·감사·회계 원장은 기존 불변식을 약화하지 않는다. 백업은 복원 테스트 없이 "성공"으로 간주하지 않는다.
- 외부 계정 생성, 운영 시크릿 주입, 실제 배포 및 법적 고지는 소유자의 명시적 권한이 필요한 비가역 작업이다. 코드 작업과 분리한다.

## 5. 경계 / Do-Not

- ✅ 해도 됨: 테스트로 재현되는 CSV/권한 결함 수정, 릴리즈 검증 자동화, 운영 문서·체크리스트, 검증된 보안 헤더 추가.
- ⚠️ 먼저 물어봐: 데이터 보존 기간, 개인정보 처리방침·약관의 법률 문안, 가용성/SLA, 운영 계정·도메인·결제/가격, 고객 데이터를 사용하는 파일럿.
- 🚫 절대 금지: 운영 환경 직접 조작, 시크릿 커밋·로그 출력, 테스트 완화/게이트 우회, 회계 계산식·기존 테넌트 데이터의 임의 변경.

## 7. 기술 접근 (HOW)

- #171은 프런트에서 모든 페이지를 받은 뒤 필터링하는 방식이 아니라, 각 전체 내보내기 API에 현재 화면과 같은 필터를 전달하고 백엔드 쿼리에 푸시다운한다. 상한 판정은 필터된 `totalElements`를 기준으로 한다.
- #172는 CRM의 `CrmDataScopeResolver`가 요약·분석 repository 호출까지 전달되는 단위 테스트와 참조 엔티티의 `@Version` 통합 테스트를 실행해 재검증한다. 증거가 충족되면 코드 변경 없이 이슈를 닫는다.
- 핵심 흐름은 Testcontainers 통합 테스트(테넌트·권한·원장 불변식)와 실제 Keycloak 세션 Playwright 시나리오를 분리한다. 전자는 CI 필수, 후자는 배포 후보의 수동/환경 통합 게이트다.
- 운영 산출물은 `docs/`의 복구 런북·파일럿 온보딩·릴리즈 체크리스트다. 보안 헤더는 Next.js 설치 버전의 실제 설정 API와 인증 콜백/CSP 호환성을 먼저 확인한 뒤 최소 정책으로 추가한다.
