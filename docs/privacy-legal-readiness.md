# 유료 파일럿 개인정보·법률 준비 기준

> 상태: **BUSINESS SCOPE APPROVED — 법률 전문가의 최종 문안 검토 전에는 계약·출시하지 않는다.**
>
> 승인 범위: 대한민국 소규모 무역·유통업 고객 1개사, Finance·Inventory·CRM 모듈
>
> 비범위: HR 모듈, 급여·인사 데이터, 민감정보·고유식별정보, 미성년자 데이터

이 문서는 제품의 처리 범위와 법률 검토 입력을 고정하는 운영 기준이지 이용약관·개인정보 처리방침·법률 자문 자체가 아니다. 최종 법적 역할, 국외 이전 근거, 책임 한도와 통지 시한은 대한민국 개인정보 보호법에 자격이 있는 전문가가 실제 계약 주체와 고객 업무를 확인해 확정한다.

## 1. 승인된 파일럿 범위

| 항목 | 결정 |
|---|---|
| 계약·서비스 국가 | 대한민국 |
| 고객 업종 | 소규모 무역·유통업 |
| 제공 모듈 | Finance, Inventory, CRM, 공통 인증·결재·감사. IAM 변경은 운영자 대행 |
| 제외 모듈 | HR 전체 |
| 정보주체 | 고객사 사용자, 고객·공급업체·잠재고객의 업무 담당자 |
| 사용 목적 | 계정·권한 관리, 회계·세금계산서·재고·영업 업무 처리, 감사·보안·지원 |
| 금지 데이터 | 주민등록번호·여권번호·운전면허번호, 건강·생체·사상 등 민감정보, 급여·인사평가, 미성년자 정보 |

고객이 HR 권한을 요청하거나 금지 데이터를 처리하려면 파일럿 범위를 변경하기 전에 별도 개인정보 영향 검토, 계약·처리방침 개정, 접근권한·보존·삭제 검증을 다시 승인한다.

| 대표자·사업장 | 대표자명, 주소, 사업자번호, 회사 전화 | 세금계산서·거래처 관리 | 법인 정보라도 자연인 식별 가능성을 고려 |
| 영업 기록 | 리드 이름·연락처, 통화·이메일·미팅 제목과 메모 | 영업 파이프라인·후속 활동 | 자유입력란에 민감정보·고유식별정보 입력 금지 안내 |
| 기술 데이터 | 인증·접속·오류 로그에 포함될 수 있는 사용자 ID, IP, 요청 시각 | 보안·장애 대응 | 실제 플랫폼 로그 필드를 #189에서 확인하고 최소화·보존기간 적용 |

현재 스키마 점검에서는 HR 밖에 주민등록번호·여권번호·건강정보 필드가 없다. 다만 메모·설명 같은 자유입력란은 금지 데이터를 기술적으로 완전히 차단하지 못하므로 계약, 사용자 안내, 운영 점검을 함께 적용한다.

## 3. 법적 역할과 계약 구조

아래는 법률 검토를 위한 권장 구조이며 최종 판단이 아니다.

1. 고객사는 자기 임직원과 거래처 담당자 데이터의 처리 목적·수단을 정하는 개인정보처리자다.
2. ERP 사업자는 고객 지시에 따라 업무 데이터를 호스팅·처리하는 수탁자다.
3. ERP 사업자는 자체 계약 담당자·청구·지원 계정 정보에는 별도 개인정보처리자가 될 수 있다.
4. Vercel·Railway와 독립 백업/지원 도구 사업자는 ERP 사업자의 재수탁자 또는 하위처리자 후보이므로 실제 계약과 데이터 흐름을 기준으로 확정한다.

고객 계약에는 최소한 위탁 목적·범위, 목적 외 처리 금지, 재위탁 조건, 접근 제한과 안전조치, 점검·감사, 사고 통지, 반환·삭제, 책임을 포함한다. 고객이 수탁자와 위탁 업무를 공개하고 ERP 사업자가 하위처리자를 관리·감독할 방법도 정한다.

## 4. 국외 처리와 하위처리자

현재 권장 인프라는 국외 처리를 전제로 한다. Vercel은 미국을 주 처리 시설로 밝히고 있고, Railway도 미국 중심 처리 및 국외 이전 가능성을 명시한다. Railway의 아시아 실행 리전은 현재 싱가포르다. 프런트엔드가 BFF로 동작하므로 Vercel도 로그인 세션과 업무 API 응답 처리 경로에 포함된다.

| 사업자 | 예상 처리 | 국가·리전 | 출시 전 증거 |
|---|---|---|---|
| Vercel Inc. | Next.js BFF, 인증 세션, 요청·응답, 운영 로그 | 미국 중심, 선택한 함수 리전 | Pro 계약/DPA, 실제 함수 리전, 하위처리자 목록·변경 알림 |
| Railway Corporation | 백엔드, PostgreSQL, Keycloak, 볼륨·로그 | 계정 처리는 미국, 실행·DB는 싱가포르 권장 | Pro 계약/DPA, 모든 서비스·볼륨 리전, 하위처리자 목록·변경 알림 |
| 독립 백업 저장소 | 암호화 PostgreSQL 백업 | 미정 | 사업자·국가·암호화 키 소유자·DPA·삭제 기한 확정 전 출시 금지 |
| 지원 채널 | 지원 요청과 첨부자료 | 미정 | 사업자·국가·개인정보 금지/마스킹 절차 확정 전 고객 사용 금지 |

법률 전문가는 개인정보 보호법 제28조의8에 따른 국외 이전의 적법 근거와 고지·동의 방식을 실제 B2B 관계에 맞게 선택해야 한다. 계약 이행 필요성을 근거로 삼을 수 있는지, 별도 동의가 필요한지 코드나 이 문서에서 단정하지 않는다. 이전받는 자, 국가, 항목, 목적, 보유기간, 거부 방법과 효과 등 최종 고지 항목을 검토하고 증거를 보관한다.

## 5. 필요한 법률 문서

법률 전문가에게 전달할 확인 질문, 산출물 목록과 승인 증거 형식은 [유료 파일럿 법률 검토 인계서](legal-review-handoff.md)를 사용한다.

- B2B 유료 파일럿 계약 또는 주문서: 제공 모듈·지원·가격·책임·종료 조건
- 개인정보 처리위탁/DPA: 고객사와 ERP 사업자의 역할·지시·보안·재위탁·삭제·감사
- 개인정보 처리방침: ERP 사업자가 직접 수집하는 계정·지원·웹 서비스 데이터와 정보주체 권리
- 국외 이전/보관 고지 또는 동의 문안: Vercel·Railway·백업·지원 사업자의 실제 국가와 보유기간
- 하위처리자 목록: 변경 통지와 이의제기 절차 포함
- 보안 사고 부속서: [서비스 운영 정책](service-policy.md)의 P1 운영 통지와 법정 신고를 구분
- 데이터 반출·파기 부속서: 운영 데이터 30일, 백업 최대 90일 정책과 법정 보존 예외
- 책임 제한·면책·준거법: 법률 전문가와 제품 소유자가 별도 승인

공개 약관만으로 고객의 업무 데이터 처리위탁 계약을 대체할 수 있는지는 법률 검토자가 판단한다. 서명 원문, 고객 개인정보, 신분증, 계약 금액은 저장소나 공개 GitHub 이슈에 올리지 않고 접근 제한된 계약 저장소의 문서 ID·버전·승인자만 운영 티켓에 기록한다.

## 6. 출시 차단 게이트

- [ ] 대한민국 법률 전문가가 실제 계약 주체와 사업자등록 정보를 확인했다.
- [ ] [법률 검토 인계서](legal-review-handoff.md)의 질문별 결론과 산출물 상태가 기록됐다.
- [ ] 최종 계약·DPA·처리방침·국외 이전 문안의 버전, 승인자, 효력일이 기록됐다.
- [ ] Vercel·Railway DPA와 최신 하위처리자 목록을 저장하고 변경 알림을 구독했다.
- [ ] Railway의 백엔드·DB·Keycloak·볼륨이 승인된 리전에 있고 Vercel 함수 리전을 확인했다.
- [ ] 독립 백업 저장소와 지원 채널의 사업자·국가·DPA·보존기간을 확정했다.
- [ ] Railway의 `3개월` 백업 보존 계산과 계약상 최대 보존일을 실제 설정으로 대조해 일치시켰다.
- [ ] 고객 사용자에게 배정된 역할의 `hr:*`·`iam:write` 권한이 0개이고 HR 데이터가 0건임을 개통 전후 확인했다. 테넌트마다 별도로 만든 프로비저닝 운영자 `SUPER_ADMIN`은 고객에게 제공하지 않는 break-glass 예외로 기록한다.
- [ ] 민감정보·고유식별정보·HR 데이터 입력 금지와 자유입력란 주의사항을 관리자 교육에 포함했다.
- [ ] 정보주체 요청, 고객 종료, 백업 재복원 시 재삭제 절차를 #189에서 리허설했다.
- [ ] 고객 동의·서명 증거의 저장 위치와 접근권한을 운영 티켓에 기록했다.

하나라도 완료되지 않으면 첫 유료 파일럿 계약·고객 데이터 입력·운영 출시를 승인하지 않는다.
