# 유료 파일럿 온보딩 체크리스트

이 문서는 운영자 보조 방식으로 첫 유료 고객사를 개통할 때 사용하는 실행·승인 기록이다. 고객 데이터나 시크릿은 이 문서에 적지 않고 승인 티켓·시크릿 저장소의 참조만 남긴다. 체크되지 않은 필수 항목이 있으면 고객 계정을 활성화하지 않는다.

## 1. 계약·데이터 범위 승인

- [ ] 계약 주체, 사용 국가, 업종, 파일럿 시작·종료일을 승인 기록에 남겼다.
- [ ] 사용할 모듈(HR·Finance·Inventory·CRM)과 사용자 수를 확정했다.
- [ ] 수집할 개인정보 범위와 처리 목적, 보유·파기 기준을 법률 검토된 약관·개인정보 처리방침에 반영했다.
- [ ] 지원 채널·지원 시간·장애 통지 기준과 서비스 수준 약속을 고객과 합의했다.
- [ ] 백업 주기·보존 기간·RPO·RTO와 고객 데이터 반출·종료 절차를 승인했다.

법률 문안과 서비스 수준 수치는 제품 코드가 결정하지 않는다. 승인된 문서나 담당자가 없으면 이 단계는 미완료다.

## 2. 운영 환경 준비

- [ ] [배포 가이드](deployment.md)에 따라 Railway·Vercel·Keycloak 환경과 도메인을 준비했다.
- [ ] DB, Keycloak, 프런트, 백엔드 시크릿이 플랫폼 변수 또는 승인된 시크릿 저장소에만 있다.
- [ ] 후보 commit SHA와 실제 Railway·Vercel 배포 SHA가 일치한다.
- [ ] 백엔드·프런트·Keycloak 헬스체크와 TLS 인증서를 확인했다.
- [ ] ERROR·5xx·지연·DB 연결 고갈 알림의 수신자와 당번을 지정했다.
- [ ] [복구 런북](operations-runbook.md)에 따른 격리 복원 연습이 성공했다.

## 3. 고객사와 최초 관리자 생성

1. Keycloak에 최초 관리자 사용자를 생성하고 사용자 ID(`sub`)를 기록한다.
2. [배포 가이드의 테넌트 생성 명령](deployment.md#1-5-최초-테넌트-생성)을 운영자 단말에서 실행한다.
3. 명령 결과와 감사 로그를 확인한다.

- [ ] 고객사 코드·이름·요금제가 승인 내용과 일치한다.
- [ ] `common.tenant.status`가 `ACTIVE`이고 중복 고객사 코드가 없다.
- [ ] Keycloak 사용자 속성 `tenant_id`와 ERP 테넌트 ID가 일치한다.
- [ ] 최초 관리자에게 해당 테넌트의 `SUPER_ADMIN` 역할과 전체 권한만 부여됐다.
- [ ] CREATE·UPDATE 감사 로그에 운영자 식별자와 테넌트가 기록됐다.
- [ ] 프로비저닝 서비스 계정 시크릿을 일반 백엔드 런타임에 남기지 않았다.

부분 실패 시 고객 로그인을 안내하지 않는다. `FAILED` 원인을 제거한 뒤 `ERP_PROVISION_RETRY=true`로 재시도하고, 임의 SQL 수정은 금지한다.

## 4. 기준정보와 사용자 권한

- [ ] 회사 프로필·기준통화·부가세 통제계정을 설정했다.
- [ ] 회계연도·기간과 계정과목, 거래처, 품목·단위, 창고·로케이션을 검토했다.
- [ ] 실제 업무별 최소 권한 역할을 만들고 작성·결재·지급 담당자를 분리했다.
- [ ] 각 사용자 Keycloak `tenant_id`가 고객사 ID와 일치하며 다른 고객사 ID를 공유하지 않는다.
- [ ] CSV/Excel 초기 데이터는 사본 환경에서 검증한 뒤 가져왔고 오류 행을 해결했다.

## 5. 고객사 UAT

- [ ] 테넌트 A/B 사용자로 같은 조회를 실행해 상대 데이터 노출이 0건임을 확인했다.
- [ ] 매입계산서 생성 → 상신 → 타 사용자 승인 → GL 상신·전기 → 시산표 반영을 확인했다.
- [ ] 매출계산서 생성 → 승인 → 수금과 재무제표 반영을 확인했다.
- [ ] 입고 → 창고간 이전 → 출고/조정 후 위치별 재고 수량을 DB·화면과 대조했다.
- [ ] 과세 매입·매출의 부가세 신고 집계와 원거래 합계를 대조했다.
- [ ] 화면 필터와 CSV 전체 내보내기 결과가 일치하고 5,000행 초과가 명시적으로 차단되는지 확인했다.
- [ ] 감사 로그에서 수행자·대상·변경 전후·traceId를 확인했다.
- [ ] 로그아웃·세션 만료·권한 없는 메뉴/API 접근이 안전하게 거부되는지 확인했다.

UAT 증거에는 고객 개인정보·토큰·시크릿 원문을 첨부하지 않는다. 건수, 해시, 마스킹된 캡처와 승인자만 기록한다.

## 6. 개통 승인과 초기 관찰

- [ ] [상용 릴리즈 준비 체크리스트](release-readiness.md)를 모두 통과했다.
- [ ] 고객 관리자 교육, 지원 연락처, 장애 신고 절차를 전달했다.
- [ ] 개통 승인자·시각·후보 SHA·테넌트 코드를 운영 티켓에 기록했다.
- [ ] 개통 후 첫 로그인·첫 업무 처리·백업 생성 성공을 확인했다.
- [ ] 초기 관찰 기간과 담당자를 지정하고 ERROR·5xx·지연·권한 거부 급증을 점검했다.
- [ ] 중단 기준 충족 시 신규 입력을 멈추고 이전 정상 배포 유지 또는 fix-forward 절차를 실행한다.

## 7. 종료·반출

- [ ] 계약 종료 승인과 고객 데이터 반출 범위를 확인했다.
- [ ] 테넌트를 먼저 비활성화해 신규 API 접근을 차단했다.
- [ ] 승인된 형식으로 데이터를 반출하고 전달 무결성을 확인했다.
- [ ] 보존 의무가 끝난 백업·계정·시크릿의 파기 증거를 남겼다.
- [ ] Keycloak 사용자와 서비스 접근을 회수하고 감사 기록을 보존했다.
